# Python Style Review

Ревью Python-кода начинается с читаемости. Хороший PR можно понять без устных пояснений автора: имена функций и переменных отражают предметную область, функции имеют ограниченный размер, а побочные эффекты явно видны по месту вызова.

Ревьюер должен просить разделить функцию, если она одновременно валидирует вход, ходит в сеть, пишет в базу и форматирует ответ. Несколько уровней ответственности в одной функции усложняют тестирование и повышают риск скрытых регрессий.

Импорты группируются по стандартной библиотеке, сторонним пакетам и локальным модулям. Неиспользуемые импорты, мёртвый код и временные debug-print должны удаляться до merge. Если импорт нужен только для typing, его можно спрятать под `TYPE_CHECKING`.

Исключения не должны проглатываться широким `except Exception` без контекста. Если ошибка ожидаемая, код должен логировать понятный event и возвращать доменную ошибку. Если ошибка неожиданная, лучше дать ей всплыть, чем скрыть проблему пустым ответом.

Ревьюер отмечает не только нарушение форматирования, но и плохой контракт. Если функция возвращает разные типы в зависимости от ветки, мутирует аргументы без предупреждения или зависит от глобального состояния, это нужно вынести в замечание.
