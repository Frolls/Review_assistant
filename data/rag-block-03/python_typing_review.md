# Python Typing Review

Аннотации типов в Python нужны не для красоты, а для фиксации контракта между модулями. Публичные функции, сервисные методы, repository-интерфейсы и DTO должны иметь понятные типы аргументов и возвращаемого значения.

`Any` допустим только на границе с внешними библиотеками, где тип реально неизвестен. Если `Any` попадает внутрь бизнес-логики, ревьюер должен попросить сузить тип через `TypedDict`, `Protocol`, `BaseModel`, dataclass или явную union-модель.

Опциональные значения должны быть выражены как `T | None`, а не скрываться в пустых строках, магических числах или пустых dict. Если `None` является валидным состоянием, код должен явно обрабатывать эту ветку.

Для коллекций в новых версиях Python лучше использовать встроенные generic-типы: `list[str]`, `dict[str, int]`, `set[UUID]`. Это упрощает чтение и согласуется с современным стилем.

Ревьюер должен проверять, что типы не врут. Если функция помечена как возвращающая `str`, но при ошибке возвращает `None` или dict, это ломает вызывающий код и должно быть исправлено до merge.
