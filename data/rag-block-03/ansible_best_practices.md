# Ansible Best Practices Review

Ansible task считается корректным, если повторный запуск playbook не меняет состояние без реальной причины. Ревьюер должен смотреть на идемпотентность, понятные task names и отсутствие скрытых изменений через `changed_when`.

Модули `command` и `shell` допустимы только когда нет специализированного идемпотентного модуля. Если shell неизбежен, task должен иметь `creates`, `removes`, явную проверку состояния или корректный `changed_when`.

Для управления пользователями используется `ansible.builtin.user`, для файлов - `copy`, `template`, `file`, для пакетов - пакетный модуль конкретной ОС. Shell-команды вроде `useradd`, `chmod`, `systemctl restart` обычно являются признаком плохого task.

Restart сервиса после изменения template должен выполняться через `notify` и handler. Иначе сервис будет перезапускаться на каждом запуске playbook, даже если конфигурация не изменилась.

Секреты не должны лежать в обычных vars-файлах. Для них используется Ansible Vault, secret manager или переменные окружения CI с маскированием. Ревьюер должен блокировать PR, где пароль или токен добавлен в plain text.
