# Secure Code Review

В PR нельзя добавлять секреты, токены, приватные ключи, cookie и реальные credentials. Если секрет уже попал в diff, ревьюер обязан попросить ротацию секрета и убедиться, что значение удалено из истории или обработано по внутреннему incident-процессу.

Любой новый outbound HTTP-клиент должен иметь timeout. Retry разрешён только для идемпотентных операций или при явной защите от повторного side effect. Для внешних URL нужен allowlist доменов, чтобы не открыть SSRF.

Пользовательский ввод нельзя напрямую передавать в shell, SQL, шаблоны или файловые пути. Для SQL используются параметры запроса, для shell лучше избегать shell=True, для путей нужна нормализация и проверка базовой директории.

Логи не должны содержать пароли, токены, приватные diff, персональные данные и полный пользовательский payload. Ревьюер должен просить redaction до записи в лог, а не после.

Ошибки API не должны раскрывать stack trace, internal URL, SQL-запросы или секретные конфигурации. Пользователю возвращается безопасное сообщение, а подробности уходят в защищённые structured logs.
