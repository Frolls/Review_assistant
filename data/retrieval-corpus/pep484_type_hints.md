# PEP 484: ревью аннотаций типов

Источник: https://peps.python.org/pep-0484/

PEP 484 определяет стандартную семантику type hints. Аннотации предназначены прежде всего для статического анализа, IDE и понимания контрактов; Python runtime сам по себе не проверяет соответствие значения типу. Ревьюер должен отличать статическую гарантию от runtime validation на внешней границе приложения.

Аннотация возвращаемого значения `async def` описывает объект после `await`, а не `Coroutine`. Если `async def load() -> User` возвращает пользователя, вызывающая сторона получает coroutine при вызове и `User` после ожидания. Явный `Coroutine` нужен, когда обычная функция действительно возвращает coroutine object.

`Optional[T]` означает `T | None`, а не «аргумент можно не передавать». Параметр с default имеет право отсутствовать при вызове независимо от того, допускает ли тип `None`. Если значение после валидации обязательно, последующие слои не должны продолжать переносить `Optional` и повторять одинаковые проверки.

`Any` отключает существенную часть статической проверки и распространяется через выражения. Он допустим на границе нетипизированной библиотеки, динамического JSON или во время ограниченной миграции, но причина должна быть локальной и понятной. Для произвольного значения, которое нельзя использовать без narrowing, безопаснее `object`.

Коллекции аннотируются типом элементов: `list[ReviewFinding]`, `Mapping[str, str]`, `Sequence[Message]`. Выбор абстрактного протокола для входа уменьшает связь с конкретной реализацией, а конкретный mutable type в результате делает владение и возможность изменения явными.

Type alias даёт имя сложной, повторяющейся форме данных и фиксирует её смысл. Однако alias для `dict[str, Any]` не описывает обязательные ключи. Для устойчивой JSON-подобной структуры следует рассмотреть `TypedDict`, dataclass или модель валидации в зависимости от того, нужна ли только статическая проверка или также runtime validation.

`TypeVar` связывает типы нескольких параметров и результата. Он оправдан, когда функция сохраняет тип входного значения или контейнера. Независимые TypeVar без реальной связи усложняют сигнатуру и не дают дополнительной гарантии. Ограничения и bound должны отражать операции, которые реализация действительно использует.

Overload описывает несколько зависимых вариантов вызова, но runtime должен иметь одну реализацию после перегруженных сигнатур. Набор overload полезен, когда тип результата меняется предсказуемо от типа или literal-значения аргумента. Если варианты отличаются только косметически, union обычно проще.

Callback можно описать через `Callable`, когда важны только аргументы и результат. Если контракт включает именованные параметры, overload или дополнительные атрибуты, callback protocol выражает его точнее. Не следует скрывать сложный callback под `Callable[..., Any]`, если библиотека реально зависит от формы вызова.

Аннотации экземпляров и class variables должны различаться. `ClassVar` сообщает анализатору, что поле принадлежит классу и не является обычным instance attribute. Изменяемое значение уровня класса требует особого внимания, поскольку разделяется между экземплярами так же, как mutable default argument функции.

Forward reference применяется, когда имя типа ещё не определено; современные версии Python также поддерживают отложенную обработку аннотаций. Ревьюер проверяет целевую версию Python и не предлагает синтаксис, несовместимый с ней. Импорты только для типов можно помещать под `TYPE_CHECKING`, если runtime import создаёт цикл или дорогой side effect.

`cast()` не преобразует значение во время исполнения, а только сообщает анализатору предполагаемый тип. Сложный или частый cast — сигнал, что runtime-инвариант плохо выражен моделью данных. PR должен объяснить гарантию и, если данные внешние, выполнить реальную проверку до cast.

`# type: ignore` подавляет диагностику и должен быть узким, иметь конкретный error code и понятную причину. Широкое подавление на всей строке или файле может скрыть новые ошибки после обновления анализатора. Предпочтительнее уточнить тип stub, добавить guard или изолировать нетипизированную интеграцию.

Type hints совместимы с docstring: аннотация фиксирует форму значения, а документация — смысл, единицы, диапазоны и побочные эффекты. Дублирование типов в prose быстро устаревает. При изменении публичной сигнатуры ревьюер проверяет вызывающий код, сериализацию и обещания обратной совместимости.
