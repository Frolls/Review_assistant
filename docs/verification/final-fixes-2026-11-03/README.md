# Исправление замечаний и проверка v12 — 3 ноября 2026

Все перечисленные в отзыве изменения реализованы и проверены. Пройдены **257
backend-тестов, 39 тестов бота и 1 интеграционный smoke**, без пропусков; Ruff
прошёл. Реальный стенд проверен через HTTP/SSE и клиент Telegram: вложения,
источники, история, инструменты, подтверждение, отмена и полная очистка.

В итоговых **36 валидных примерах** найдено **12/12 дефектов**, проверены
**12/12 исправлений**, ложных замечаний на **24 корректных фрагментах нет**.
Всего v12 обработал 38 примеров: два первоначальных «чистых» эталона оказались
неоднозначными и заменены с сохранением исходных ответов. Это ограниченные
проверки шести семейств дефектов; использована автоматизированная оценка
в том же процессе разработки, без независимой человеческой экспертизы. Показатели не означают безошибочность ревью произвольного кода.

## Дополнительные исправления после неудачного live-контроля

Результаты прежнего [контроля 3 TP / 3 FN](../acceptance-2026-11-03/README.md)
сохранены. Они выявили причины, которые устранены в коде:

- Диагностики F821/B012 и Ansible могли теряться из-за неточного retrieval или
  отказа модели признать уже проверенное нарушение. Векторный поиск сохранён,
  порог каждого кандидата остаётся 0.5. Дополнительно работает точный каталог
  четырёх правил с официальными URL, `score=null`: F821, B012, mkdir-repeat,
  secret-debug. Никаких фиктивных similarity score нет.
- Отсутствующий стандартный импорт исправляется перед использованием имени;
  сохраняются docstring и future imports. Удаление диагностированного константного
  return из finally сохраняет cleanup и распространение исключения. Вызовы с
  побочным эффектом автоматически не удаляются.
- Явные числовые примеры задачи проверяются закрытым AST-интерпретатором.
  Пользовательский Python не выполняется. Для исправления модель предлагает
  только выражение return; сигнатура и остальная структура сохраняются.
  Проверяются примеры и повторные диагностики. Это ограниченный интерпретатор,
  не sandbox для произвольного кода и не универсальная проверка контрактов.
- `no_log` учитывает наследование и переопределение задачи внутри block.
  Исправление mkdir сохраняет `chdir`, добавляет `creates` и не дублирует `cmd`.
- Агент после поиска публикует точную выдержку источника с атрибуцией. Дополнительный
  свободный пересказ, ранее добавлявший неверное утверждение об `Optional[T]`,
  не выполняется. Это извлечение источника, а не новое доказательство его истинности.
- Usage истории теперь включает LLM-подготовку поиска, condense и проверку
  достаточности контекста. В двух исходных v12-прогонах по 21 вызову; все их
  счётчики совпали с telemetry. Embeddings в эти chat-completion токены не включены.

Правила проверены по первичной документации: [Ruff F821](https://docs.astral.sh/ruff/rules/undefined-name/),
[Ruff B012](https://docs.astral.sh/ruff/rules/jump-statement-in-finally/),
[Ansible shell / creates](https://docs.ansible.com/projects/ansible/latest/collections/ansible/builtin/shell_module.html),
[Ansible no_log](https://docs.ansible.com/projects/ansible/latest/reference_appendices/logging.html#protecting-sensitive-data-with-no-log).

## Протокол и результаты

Код v12 зафиксирован [хешами до прогона новых случаев](protocol-v12.json) и после
этого не менялся. Образы не пересобирались: текущие исходники и проверенный кеш
токенизатора смонтированы read-only. Реальные PostgreSQL, Redis, Qdrant и Ollama;
подмен LLM/retriever/БД нет. Текущая конфигурация — в [manifest](manifest.json).
Ревью: Qwen2.5 14B, основной агент: Qwen3 8B, generation context фактически 8192.
Embedding-модель Qwen3 embedding 4B использует собственный контекст 4096.

После завершения live-прогонов внесена одна отдельная правка форматирования:
числовой список вроде `[7]` в диагностике выводится как inline code, чтобы
валидатор не принимал его за источник №7. Алгоритм проверок, retrieval и настройки
модели не изменены. [Хеши этой правки](post-live-format-patch.json) отделены от
замороженного v12; новая регрессия и полный backend suite прошли —
[257 passed](backend-tests-final.txt). Live-метрики ниже относятся к исходному
замороженному v12 до этой правки формата.

| Итоговый набор | TP / FP / FN | Пригодные исправления | Корректные без ложных замечаний | Медиана / p95 хода |

| Регрессии прежней приёмки, 18 | 6 / 0 / 0 | 6/6 | 12/12 | 0.545 / 5.518 с |

Новые варианты зафиксированы до просмотра их ответов. При последующей сверке

## Агент и измерения inference

Реальные backend и HTTP API бота прошли readiness, RAG со ссылкой и **9 ходов**:
память → время Екатеринбурга → новое UTC-время → поиск с точной цитатой →
восстановление метки → preview → cancel → новое preview → clear и забытая метка.
Старое подтверждение после clear отклонено с 409. Медиана хода 0.833 с,
14 LLM-вызовов, 14 568 chat-completion токенов. [Ответы](agent-live.json),
[telemetry](agent-telemetry.json), [ресурсы](agent-resources.json).
Polling, broadcasts и положительный resume не запускались; [аудит бота](bot-access.jsonl)
содержит **0 запросов `/notify`**.

Отдельный native Ollama benchmark: один warmup и три измеренных повтора
с одинаковым синтетическим prompt, temperature 0, context 8192, thinking off.
Медиана decode — **46.935 токена/с**, wall time — **3.479 с**; диапазон decode
46.930–47.036 токена/с. [Исходные native-счётчики](inference-raw.json).
Prefix cache влияет на prefill; это не end-to-end latency приложения.

| Фаза | Время всей фазы | Средняя CPU хоста | Средняя GPU busy | Пик RAM хоста / VRAM устройства |
| --- | ---: | ---: | ---: | ---: |
| Исходные 18 регрессий v12 | 78.19 с | 8.14% | 23.52% | 21.68 / 15.57 GiB |
| Исходные 18 новых вариантов | 78.72 с | 8.03% | 23.34% | 21.01 / 15.57 GiB |
| Native inference с warmup | 15.82 с | 28.00% | 89.00% | 20.48 / 11.95 GiB |

Каждый 18-case прогон включает записанное ожидание rate limit управления чатом
60 секунд; оно не включено в latency отдельного ревью. Генерации не повторялись
вслепую. Ресурсы — host/device-wide, включая другие процессы, загрузку/выгрузку
моделей и паузы; это не чистая стоимость одного inference. Энергия GPU-датчика
в native-фазе ≈0.881 Wh, не энергия всего компьютера и не денежная стоимость.
API-цена локального вызова не трактуется как нулевая стоимость вычислений.

## Воспроизведение и границы

`python3 docs/verification/final-fixes-2026-11-03/summarize.py` пересчитывает
сводку и проверяет хеши исходников, входов и согласованность usage. Для нового
live-запуска используйте `Review_bot/scripts/eval_code_review.py --cases <JSON>
--output <новый файл>` при работающем стенде и `INTERNAL_TOKEN`; результаты
сохраняйте отдельно. `scripts/measure_local.py` оборачивает команду измерениями,
`scripts/benchmark_inference.py` сохраняет native-счётчики, а
`scripts/live_agent_acceptance.py` использует настоящий клиент бота.

Исторические RAGAS CSV, включая оба неудачных уточнения, не изменены. Это не
A/B порога: изменились алгоритм ревью и проверка исправлений. Новая выборка
мала и покрывает заявленный набор проверок; произвольные семантические дефекты,
полный PR, внешние voice/vision и доставка в Telegram этим прогоном не доказаны.
Границы чистого ответа и отсутствие автоматической передачи эскалации человеку
отражены в интерфейсе и документации. На стенде использованы исходники через
mount, поэтому перед обычным развёртыванием нужен штатный build образов.
