# Исторические проверки: назначение и ограничения

Текущее состояние продукта описывает [итоговый отчёт v12](README.md).
Материалы ниже сохранены для разбора причин ошибок и подготовки новых
регрессионных сценариев. Это результаты прежних версий, а не повторная
проверка текущего кода. Сырые ответы содержат ошибки модели; их нельзя
использовать как эталон правильного ответа без проверки.

| Материал | Для чего полезен |
| --- | --- |
| [Первый live benchmark](live-review-2026-11-03/README.md) | Два прогона по 9 вложениям, включая таймаут, отказы и ложное замечание о docstring. Показывает, почему отсутствие ложных замечаний при отказах ещё не означает качественное ревью |
| [Compatibility probe](live-review-2026-11-03/compatibility-probe.json) | Зафиксированы различия параметров thinking и фактического context в OpenAI-совместимом endpoint Ollama |
| [Native inference](live-review-2026-11-03/inference-raw.json) | Warmup и повторы с thinking/без него; отдельные счётчики prefill/decode. Ресурсные трассы полного набора позволяют проверить расчёты нагрузки и энергии |
| [Разделение тем](rag-diagnostics-2026-10-04/grounding-topic-check.json) | Примеры смешения правил Python и Ansible и проверки после изменения prompt |
| [Фильтрация retrieval](rag-diagnostics-2026-10-04/retrieval-filter-check.json) | Проверки порога для отдельных фрагментов; сохранены ограничения, включая некорректный пример Ansible |
| [Границы правил](rag-diagnostics-2026-10-04/rule-boundaries-check.json) | Влияние границ документов на retrieval и неподтверждённые предположения модели |
| [Достаточность оснований](rag-diagnostics-2026-10-04/evidence-guard-check.json) | Неоднозначный запрос, существующая, но неприменимая ссылка, ошибка про Vault и diff. Полезные кандидаты для будущих проверок точности замечаний |

Первый benchmark возвращён целиком: исходные ответы, аннотации, telemetry,
ресурсы, manifest, хеши кода, сводка и скрипты. Его исторический
`artifacts-sha256.json` обновлён только для редакционных изменений атрибуции;
хеши до и после приведены в [журнале сопровождения](maintenance-2026-11-03.json).
Ответы и числовые измерения сохранены без изменений. Для четырёх октябрьских JSON
добавлен отдельный `artifact-sha256.json`: он проверяет целостность перенесённых
байтов, но не является заранее зафиксированным протоколом эксперимента.

`python3 scripts/recompute_verification.py --verify-only` из корня репозитория
проверяет хеши всех включённых наборов, включая обе формы имени манифеста.
Полный runner пересчитывает только итоговый v12. Исторические скрипты используют
старую раскладку Diploma и прежние версии кода; их команды в архивных README
не следует воспринимать как инструкции для текущего checkout.

Новые сценарии можно взять из сохранённых вопросов и примеров кода, независимо
проверить ожидаемый результат и добавить в наборы `tests/eval/code_review`.
Оценку следует проводить новым запуском с отдельными результатами. Исходный
benchmark и v12 отличаются моделями, контекстом и алгоритмом: сравнение не
изолирует влияние одного изменения и не является A/B-тестом.

Промежуточные серии v2–v10, debug-выгрузки, репетиции видео и дублирующий
хронологический отчёт сохранены в `Diploma/docs` вне Git. Текущая документация
и воспроизведение v12 от них не зависят.
