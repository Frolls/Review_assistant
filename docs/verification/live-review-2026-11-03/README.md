# Live code review и inference — 3 ноября 2026

Выполнены **два полных прогона по 9 реальным вложениям через HTTP/SSE** и
отдельный microbenchmark Ollama: по одному прогреву и три измеренных повтора
с thinking и без. Неудачные запросы сохранены. Качество пока недостаточно:
отказы на корректном коде, пропуск дефектов и одно ложное замечание.

## Стенд и протокол

- AMD Ryzen 9 9950X, 16 ядер / 32 потока, 123.23 GiB RAM.
- Дискретная AMD GPU: PCI `1002:744c`, 15.98 GiB VRAM, драйвер `amdgpu`.
  Также присутствует встроенная GPU; её показания сохранены отдельно.
- Ollama 0.40.6; `qwen3:latest`, 8.2B, Q4_K_M;
  embeddings `qwen3-embedding:4b`, Q4_K_M. Полные digest — в `manifest.json`.
- Текущий backend из рабочего дерева смонтирован в существующий образ
  `localhost/llm-service:v1`. PostgreSQL, Redis и Qdrant настоящие.
  Коллекция `corporate_rag_rules_v3`: **1818 фрагментов**; переиндексация не выполнялась.
- Порог 0.5, reranker выключен, один запрос одновременно, timeout вызова модели
  30 с, всего хода 180 с. Генерация ChatService не задаёт temperature явно.
- `LLM_NUM_CTX=8192` в конфигурации, но **фактически `/api/ps` показывает 4096**.
  Это расхождение зафиксировано, а не исправлено между измерениями.
- Собственные трассы без содержимого; Phoenix выключен. Telegram polling и
  отправка сообщений не запускались. Это benchmark backend review, не `/agent`.
- Набор заморожен до запуска: три дефекта, три исправленных и три чистых
  фрагмента. Каждый отправлялся multipart-вложением `.py`/`.yaml`, история
  очищалась перед примером. Отказы и таймаут входят в знаменатели.
- Baseline начал работу с неинициализированным токенизатором backend и без
  загруженных моделей Ollama. Во втором прогоне backend уже инициализирован,
  однако модели успели выгрузиться до его начала. Кеш embeddings мог повторно
  использоваться: во втором прогоне наблюдалась только загрузка генеративной
  модели. Это **повтор**, не изолированный A/B и не полностью прогретый стенд.

В `manifest.json` записаны конфигурация и ревизии; рабочее дерево содержит
исправления без коммита. `code-sha256.json` фиксирует проверенный код.

| Содержательные ответы | 2/9 | 3/9 |

| Ошибка общего timeout | 1/9 | 0/9 |

p95 вычислен nearest-rank: при девяти измерениях он совпадает с максимумом.
Это малый диагностический набор, не статистическая оценка качества продукта.
Оценки выставлены **автоматизированно по эталонам и возвращённым источникам**, не человеком
и не вслепую. Исходные ответы отделены от аннотаций. Нулевой FP в baseline
объясняется отказами на всех корректных примерах и не доказывает хорошее ревью.

Baseline нашёл незакрытый файл и неидемпотентный `mkdir`, но потерял пример
mutable default из-за timeout. Повтор нашёл mutable default и незакрытый файл,
отказался от замечания к `mkdir` и ошибочно потребовал docstring у чистой
функции. Приведённый для docstring источник говорит о синхронизации уже
существующей документации с сигнатурой и не доказывает названный дефект.

Три опубликованных Python-исправления из двух прогонов проверены в контейнере
без сети и доступа на запись: независимость словарей, сохранение явного cache,
результат чтения, закрытие файла при успехе и при исключении. Перед исполнением
AST сравнивался с заранее заданным эталоном. Ansible-исправление проверено
структурно: `ansible.builtin.file`, `state: directory`, путь и mode. **Ansible
на управляемом узле не запускался**; для него пригодность означает проверку
семантики параметров. Объяснение модели о статусе `changed` неточно: исходный
`mkdir` при повторе завершается ошибкой. Исправленный модуль подходит задаче.

SSE передаёт накопленный и проверенный текст в конце. Поэтому время первого
`token` здесь не является временем первого токена модели. В `cases.csv` отдельно
сохранены время первого события, первого текста и всего ответа.

Из telemetry завершённых вызовов модели: baseline **23 706 токенов**
(17 279 input + 6427 output, 22 вызова); повтор **26 667**
(19 181 + 7486, 25 вызовов). Это extraction/evidence/generation вместе,
**без embeddings и незавершённых вызовов**. Usage последней генерации отдельно
сохранён вместе с записью истории в `*-raw.json`.

## Чистый inference

Нативный `/api/chat`, тот же digest модели, context 4096, temperature 0,
seed 42, максимум 1024 выходных токена, фиксированный короткий запрос о mutable
default. Каждый режим: один отдельный прогрев, затем три повтора; прогрев
сохранён, но исключён из следующей таблицы. RAG и валидации приложения нет.

| Режим | Медиана wall time | Средняя скорость decode | Выходных токенов на повтор |
| --- | ---: | ---: | ---: |
| Native `think=false` | 1.173 с | 79.83 токена/с | 92 |
| Native `think=true` | 4.204 с | 78.72 токена/с | 329, включая reasoning |

Скорость — `eval_count / (eval_duration / 1e9)`, а не деление длины текста на
время. Нативные duration/load/prefill/decode сохранены в `inference-raw.json`.
Повторяется одинаковый prompt, поэтому prefill использует кеш и его скорость
не обобщается на новые запросы. Это не измерение конкурентной пропускной
способности и не замена времени ответа приложения.

## Ресурсы и энергия

Сэмплирование примерно каждые 0.5 с на хосте модели; перед каждой серией
сохранены пять секунд исходной нагрузки. CPU нормирован на все 32 потока.

| Показатель | Baseline, 278.02 с | Повтор, 106.52 с | Inference, 22.95 с |
| --- | ---: | ---: | ---: |
| CPU хоста, среднее | 10.92% | 29.31% | 30.27% |
| RAM хоста до серии / пик, GiB | 12.88 / 14.91 | 13.68 / 15.50 | 14.89 / 15.27 |
| GPU busy, среднее / пик | 36.61% / 99% | 95.43% / 99% | 94.24% / 99% |
| Пик VRAM дискретной GPU, GiB | 12.23 | 8.65 | 8.52 |
| Мощность GPU, средняя по времени / пик, W | 93.22 / 234 | 214.38 / 227 | 215.02 / 223 |
| Энергия GPU по датчику, Wh | 7.20 | 6.34 | 1.37 |
| Оценка энергии сверх исходной нагрузки, Wh | 4.68 | 5.32 | 1.04 |

В третью колонку входят и два прогрева. Первая серия включает долгий простой
до inference. RAM, VRAM, CPU и мощность относятся ко всему хосту/устройству,
включая рабочий стол и другие процессы. Энергия рассчитана трапециями по
`power1_average`; это показание GPU, **не энергия всей системы от розетки**.
Оценка сверх исходной нагрузки зависит от короткого baseline и не является
точным учётом энергии одного запроса. Денежная стоимость не рассчитана:
тариф электроэнергии и амортизация не заданы. Нулевой счёт API не означает
нулевых затрат на вычисления.

## Обнаруженные ограничения

1. Первый запрос заблокировал обработку примерно на 183 с до обращения к
   модели. `/api/ps` оставался пустым, heartbeat пришёл вместе с ошибкой.
   Файл кеша tiktoken появился в `09:03:58.429974 UTC`, непосредственно перед
   окончанием запроса в `09:03:58.551088 UTC`. Код синхронно вызывает
   `tiktoken.get_encoding` при первом подсчёте. Это сильное свидетельство
   задержки инициализации/загрузки токенизатора; отдельный сетевой trace не
   снимался. Общий asyncio timeout не прерывает блокирующий синхронный вызов.
2. Compatibility probe подтвердил: `/v1/chat/completions` с `think=false`
   вернул 953 символа reasoning и упёрся в лимит 256 токенов; тот же запрос
   с `reasoning_effort=none` вернул ответ без reasoning и завершился `stop`.
   Значит, текущий способ отключения thinking не работает на этом endpoint.
3. Там же `options.num_ctx=8192` не изменил наблюдаемые 4096. Budget приложения
   и реальный context модели необходимо согласовать.
4. Проверка ссылок не заменяет проверку их применимости: ложное замечание о
   docstring имело существующий номер источника. Корректные фрагменты часто
   превращаются в отказ из-за evidence/citation policy.

Эти результаты не исправлялись отбором примеров, исключением отказов или
подстройкой порога. Исторический RAGAS на 35 вопросах не пересчитывался и
не смешивался с новым benchmark.

## Артефакты и воспроизведение

- `baseline-raw.json`, `repeat-raw.json`: ответы, события SSE, request_id,
  задержки, итоговый объект и usage из сохранённой истории.
- `*-annotated.json`: отдельные оценки и объяснения; `fix-validation.json`:
  результаты проверок кода; `validate_fixes.py`: сами проверки.
- `*-telemetry.json`: события backend только запросов benchmark.
- `resources-*.json`: сырые CPU/RAM/GPU/process/API snapshots и idle baseline.
- `inference-raw.json`, `compatibility-probe.json`: нативные счётчики и проверка
  параметров совместимого endpoint.
- `summary.json`, `cases.csv`: пересчитываемые итоги; `manifest.json` и
  `code-sha256.json`: параметры и код.

Пересчитать таблицы без запуска модели, из корня workspace:

```sh
python3 docs/verification/live-review-2026-11-03/summarize.py
```

Новый live прогон на уже готовом backend с `INTERNAL_TOKEN` в окружении:

```sh
python3 scripts/measure_local.py --output resources-new.json \
  --ollama-url http://localhost:11434 --baseline-seconds 5 -- \
  python3 Review_bot/scripts/eval_code_review.py --output review-new.json
python3 scripts/measure_local.py --output resources-inference-new.json \
  --ollama-url http://localhost:11434 --baseline-seconds 5 -- \
  python3 scripts/benchmark_inference.py --output inference-new.json
```

Измеритель запускается именно на хосте модели. HTTP-клиенту нужны зависимости
backend; в этом прогоне он запускался в существующем контейнере с host network
и `.env`, а измеритель — снаружи. Ключи в артефакты не записываются.
Для совпадения условий нужны текущие исходники, сохранённый индекс и настройки
из manifest; один digest модели не гарантирует одинаковые ответы.

Ruff прошёл для обоих измерителей, клиента benchmark и скриптов анализа.
Поведенческие проверки опубликованных Python-исправлений и структурная проверка
Ansible прошли. Live `/agent`, Telegram polling и нагрузка при нескольких
одновременных пользователях в этот эксперимент не входят.
